# 屏幕共享 Demo 项目说明

这是一个基于 Qt 6 的本地屏幕共享演示项目，主要用于课程 Demo 和小组展示。项目包含登录注册、屏幕/窗口/白板共享、画笔标注和共享预览等功能。

## 1. 运行环境

建议环境：

- Qt 6.11.1
- Qt Creator 19.x
- MSVC2022 64-bit Kit
- CMake 3.16 及以上
- Windows 10 / Windows 11

打开工程时请选择根目录下的：

```txt
CMakeLists.txt
```

不要打开：

```txt
CMakeLists.txt.user
```

`.user` 文件是别人电脑上的 Qt Creator 本地配置，换电脑后经常失效。

## 2. 项目功能概览

目前项目支持：

1. 登录 / 注册
2. 本地账号保存
3. 屏幕 1 共享
4. 扩展屏检测，只有接入扩展屏时才显示屏幕 2
5. 白板共享
6. 当前窗口共享
7. 画笔标注
8. 标注笔迹合成进共享画面
9. 共享预览区和顶部小窗口同步显示

## 3. 主要文件结构

```txt
main.cpp                    程序入口
loginwindow.ui              登录/注册界面控件布局
loginwindow.h/.cpp          登录、注册、本地 users.json 逻辑
mainwindow.ui               主界面控件布局
mainwindow.h/.cpp           共享、白板、窗口列表、画笔接入逻辑
annotationwindow.h/.cpp     画笔浮动窗口和工具栏
annotationoverlay.h/.cpp    真正的绘图层，处理鼠标绘制、橡皮擦、文字、撤销重做
receiverwindow.*            接收端窗口示例
senderwindow.*              发送端窗口示例
CMakeLists.txt              CMake 构建配置
```

## 4. 登录注册逻辑

登录界面使用 `loginwindow.ui` 控件版实现，可以在 Qt Designer 里继续拖拽修改。

账号数据保存在本地：

```txt
users.json
```

密码不是明文保存，而是使用：

```txt
salt + SHA256 hash
```

所以这个登录功能适合作为课程 Demo，不是联网后台登录。

## 5. 主界面共享逻辑

主界面由 `mainwindow.ui` 和 `mainwindow.cpp` 控制。

点击“共享”后，会弹出共享选择框，里面包含：

```txt
屏幕 1
屏幕 2：仅检测到扩展屏时显示
白板
已打开窗口列表
```

### 5.1 屏幕共享

屏幕共享使用：

```cpp
QScreen::grabWindow(0)
```

它会定时截取整个屏幕画面，然后显示到主界面的大预览区和顶部小窗口。

### 5.2 窗口共享

窗口共享在 Windows 下优先使用：

```cpp
PrintWindow(hwnd, ...)
```

如果抓到黑屏，会退回到屏幕区域裁剪方案。

需要注意：部分浏览器视频、管理员权限窗口、受保护窗口可能仍然抓不到，这是 Windows 系统限制。真正会议软件一般会用 Windows Graphics Capture API。

### 5.3 白板共享

白板不是抓屏，而是创建一张白色画布：

```txt
白色背景 + 画笔笔迹 = 白板共享画面
```

白板模式下，画笔只能在中间的大白板区域绘制，不能画到按钮区或者窗口外部。

## 6. 画笔标注逻辑

画笔功能由两个类组成：

```txt
AnnotationWindow    画笔透明窗口 + 浮动工具栏
AnnotationOverlay   真正保存笔迹并绘制的透明图层
```

画笔支持：

- 红色、蓝色、黄色、绿色
- 笔宽调节
- 橡皮擦
- 文字标注
- 撤销
- 重做
- 清空
- 退出

共享画面不是单纯依赖系统把透明窗口抓进去，而是在程序里做了合成：

```txt
原始共享画面
+ annotationWindow->annotationPixmap()
= 最终共享画面
```

这样窗口共享、屏幕共享、白板共享都能看到画笔笔迹。

## 7. 关于“画笔时不能操作浏览器”的说明

打开画笔时，程序会在目标窗口上方盖一层透明绘图层。这个绘图层需要接收鼠标事件，否则就无法画线。

所以会出现：

```txt
画笔开启：鼠标用于画线，不能点击/滚动下面的浏览器
画笔关闭：鼠标还给浏览器，可以点击、滚动、输入
```

这是正常现象，因为同一个鼠标事件不能同时既用来画线，又传给下面的浏览器操作。

当前项目的推荐使用方式是：

```txt
需要标注 → 点击“画笔”
需要操作网页/窗口 → 点击“关闭画笔”
继续标注 → 再点击“画笔”
```

注意：“关闭画笔”只是隐藏绘图层，不会清空已经画出的笔迹。已经画出的笔迹仍会继续合成到共享画面里。

如果要删除笔迹，请点画笔工具栏里的：

```txt
清空
```

## 8. 卡顿原因和优化说明

当前 Demo 有轻微卡顿，主要原因是：

1. 窗口共享需要频繁调用 `PrintWindow` 或 `grabWindow`
2. 每帧都要把共享画面缩放到主预览区和小窗口
3. 画笔开启时还要额外合成透明笔迹图层
4. Qt 主线程同时负责 UI、抓屏、缩放、绘制

本版本已经做了几个轻量优化：

```txt
1. 降低抓屏频率到约 6fps
2. 避免鼠标每移动一个点就立即抓屏
3. 预览缩放改用 FastTransformation，减少 CPU 压力
4. 画笔笔迹仍然由定时器统一合成进共享画面
```

后续如果要继续优化，可以考虑：

### 方案 A：降低帧率

适合课程 Demo，简单稳定。

```cpp
shareTimer->setInterval(160); // 约 6fps
shareTimer->setInterval(100); // 约 10fps
shareTimer->setInterval(66);  // 约 15fps，更流畅但更耗 CPU
```

### 方案 B：不要每帧更新所有小窗口

当前顶部 5 个小窗口都显示相同画面。为了省性能，可以只更新主预览区和第一个小窗口。

### 方案 C：把抓屏放到工作线程

可以做，但要注意 Qt 限制：

```txt
QPixmap 和 QWidget 相关操作必须在主线程
工作线程更适合处理 QImage、图像压缩、图像合成等非 UI 任务
```

推荐结构是：

```txt
主线程：负责定时器、UI 更新、最终 setPixmap
工作线程：负责耗时的截图处理、QImage 缩放、编码、合成
```

### 方案 D：使用 Windows Graphics Capture API

这是更接近真实会议软件的方案，性能和稳定性都比 `PrintWindow` 更好，但代码复杂度明显更高，不太适合短期课程 Demo。

## 9. 常见问题

### Q1：为什么共享 Qt Creator / 浏览器有时黑屏？

因为普通的 `grabWindow` 或 `PrintWindow` 对硬件加速窗口不一定稳定。项目里已经做了 fallback，但仍然不能保证所有窗口都能抓到。

### Q2：为什么最小化窗口不能直接共享？

Windows 下最小化窗口通常没有实时绘制内容。项目会先恢复最小化窗口，再尝试抓取。

### Q3：为什么画笔时不能滚动网页？

因为透明绘图层正在接收鼠标事件。要滚动网页，需要先点“关闭画笔”。

### Q4：关闭画笔后笔迹会不会消失？

不会。关闭画笔只是停止编辑，笔迹仍然保留并继续显示在共享预览中。

### Q5：怎么彻底清除笔迹？

打开画笔后，点击工具栏里的“清空”。
